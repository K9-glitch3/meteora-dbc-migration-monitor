16 October 2026 / v0.3

A usable read-only developer workflow

I am continuing DBC Migration Monitor regardless of the Colosseum outcome. Version 0.3 connects saved watchlists, sampled readiness, migration evidence, a versioned read API and supported quote comparisons. This is dated post-submission development, not work I am claiming was completed during the judged period.

I have checked 40 exact-input cases across five captured pools against Meteora's pinned DAMM v2 SDK, using the same account bytes, amounts, direction and fee inputs. All 40 match; 26 snapshots are explicitly excluded from this narrow static-fee, standard-SPL scope. These are arithmetic checks, not fills, profitability or an independent audit.

The readiness sample contains three pool/config pairs captured in one finalized RPC context. Threshold indicators and migrated flags remain separate from verified transaction identities. The public feed is manually refreshed from bounded captures, not a continuous hosted stream. Browser activity does not run after the page closes.

The suite now has 72 tests. Reconnect history recovery has explicit request budgets and unresolved outcomes. I also hardened missing-metadata handling and preserved pool identity in unknown readiness states. The published dependency review records the remaining offline-SDK advisory and licensing questions.

I also completed a full one-hour mainnet observation, 04:50:52-05:50:52 UTC: 58 migration candidates, 55 finalized identity matches, three failed transactions and 2,566 pool-state observations across 55 pools. There were no recorded RPC errors, reconnects or queue overflows. Another 80 supported quote cases match the SDK, with 45 snapshots excluded. Across the two captures, all 120 compared cases match.

The hour's raw capture, replay output and exact collector launch source are preserved. The release evolved while collection ran, so this is not a claim that every later recovery fix ran for an hour. No recovery occurred in this capture; recovery behaviour is covered by fault-injection tests. There is no independent ground-truth stream or measured missed-event rate.

Earlier v0.2 milestones

16 October 2026 / Milestone 1

Versioned observations and automated verification

I have added a versioned observation schema to DBC Migration Monitor. Every record now carries its source, slot, commitment, freshness, result, reason and comparison scope. This makes missing and unsupported evidence explicit instead of turning it into a success.

I have also added automated tests and Windows/Linux CI on Python 3.10 and 3.12. The release suite now contains 44 tests, including malformed inputs, stale evidence, slot conflicts, cancellation and checksum tampering.

The supported comparison in this release is migration identity. It is not a claim that swap quotes or trading outcomes have been verified.

16 October 2026 / Milestone 2

Read-only collection and reproducible replay

I have added a bounded, read-only Solana collector. It discovers DBC migration candidates, retrieves finalized transactions, checks supported instruction roles, and records DAMM v2 pool snapshots and account updates.

The collector preserves duplicates, conflicts, missing evidence and connection gaps as distinct outcomes. Reconnection is implemented and tested, but there is no claim of complete network coverage or historical gap backfill.

Each completed run can be frozen into a checksummed capture, observation file and manifest. Anyone can run the same offline replay and verify the published classifications. The package contains no wallet, signing or transaction-submission path.

16 October 2026 / Milestone 3

Public evidence explorer and transaction-level fixtures

I have published an interactive evidence explorer with search, result/stage/freshness filters, pagination, per-record details, transaction links and filtered JSON downloads. The page displays recorded evidence rather than pretending to be a live feed.

The public repository now includes raw mainnet responses and deterministic observations, with a separate, clearly labelled synthetic fixture for failure cases such as invalid owners, unsupported layouts and stale slots.

Pool prices are exposed as exact atomic-unit ratios, preserving integer precision. They are not labelled as independently verified swap quotes. The explorer has been checked on desktop and mobile layouts.

16 October 2026 / Milestone 4

Thirty-minute mainnet run: results and limitations

I completed a 30-minute read-only mainnet run on 16 October 2026, from 02:48 to 03:18 UTC. It observed 34 migration candidates: 31 matched finalized migration identities, two transactions failed, and one finalized transaction remained unavailable.

The capture also contains 325 pool-state observations across 31 distinct pools, including confirmed updates from up to four watched pools. Ten RPC errors are retained. There were no reconnects or queue overflows in this run, so those paths are covered by tests rather than claimed as demonstrated by this capture.

The public corpus contains 411 capture records and 403 derived observations with checksums and reproducible replay. This is evidence of the monitor's current behaviour, not an accuracy benchmark, independent audit or swap-price verification. My next validation target is independent same-state quote comparison and external developer pilots.
